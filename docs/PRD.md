# PRD · Pokémon Lab（宝可梦研究所）

> 状态：MVP 阶段（P0 已交付）。本文档描述产品目标、功能边界与验收标准，技术细节见 ARCHITECTURE.md。

## 1. 产品定位

一个**本地优先**的个人宝可梦工具站：先让自己每天愿意打开（查资料、算克制、做笔记、考试），
再逐步变成 AI 实验平台（LLM 战术教练、自动对战、强化学习）。

## 2. MVP 功能（P0–P6 交付）

| 功能 | MVP 范围 | 明确不做 |
| --- | --- | --- |
| 图鉴与搜索（P2） | 列表分页、名称搜索、属性/世代筛选、详情（属性/种族值/特性/进化链） | 全世代覆盖、招式详表 |
| 属性克制计算器（P1 引擎 + P3 UI） | 进攻 × 1~2 防守 → 倍率；反向「谁克我」；世代维度 | 伤害公式、道具/特性修正 |
| 收藏与笔记（P4） | 收藏宝可梦、备注、自由笔记、标签 | 完整账号体系、社交 |
| 大师考试 v0（P5） | 规则模板组卷（选择/判断）、评分、错题本、来源展示 | LLM 出题、主观题 |

## 3. 后续扩展（不在 MVP）

- LLM 战术教练：结构化工具 + 有依据的回答，答案关联具体规则版本
- Pokémon Showdown 自动对战：模拟器 + Python 适配器 + 策略对比
- 强化学习：Gymnasium 环境、PPO 基线、训练/评估分离
- 安卓 / PWA：复用同一套 Web 代码
- 中英文切换：文本集中组织，MVP 不引入 i18n 框架

## 4. 核心约束（非功能需求）

1. **数据真实可追溯**：不虚构数据来源；演示数据必须显式标记；每条考试题目可回溯到具体事实。
2. **世代与规则版本**：数据结构从一开始就带 `generation` / `ruleset` 维度；未实现的世代不宣称支持。
3. **前后端职责清晰**：业务逻辑放在领域层/特性层纯函数，不写在页面组件中。
4. **关键计算必须有单测**：属性倍率、组卷评分等，后端 pytest 与前端 Vitest 共用测试向量。
5. **统一设计系统**：设计令牌集中定义；桌面 + 手机浏览器响应式。
6. **外部 API 健壮性**：超时、失败分类、加载/空/错误状态、缓存与降级。
7. **依赖克制**：不提前引入 Redis、消息队列、向量库等组件。

## 5. 验收清单（P6 对照）

| 验收项 | 通过标准 |
| --- | --- |
| 图鉴 | 可搜索、可开详情，数据来源明确标注 |
| 属性计算 | 已知用例通过，双属性逻辑正确 |
| 收藏笔记 | 刷新后仍保留（后端 SQLite 持久化） |
| 大师考试 | 答题、评分、错题记录完整 |
| 手机体验 | 常用页面在手机浏览器可用 |
| 工程质量 | 启动说明 + 基本测试 + Git 历史 |

## 6. 匿名身份（MVP 边界）

不做登录：前端生成匿名 UUID（localStorage），以 `X-Owner-Key` 头携带，后端按 key 隔离个人数据。
该标识不具备防伪能力，只用于区分「不同浏览器上的数据」。换浏览器/清缓存会得到新身份 —— 此限制写入 README。
